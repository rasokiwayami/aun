# 受け入れ条件と検証範囲

元の52件は[設計上の受け入れ仕様](acceptance-cases.json)です。表の「機構検証」は合成データで実装機構を検査したという意味で、元仕様の意味的・実利用上の期待をすべて証明したという意味ではありません。

検証は `npm test` で実行します。テスト名の対応先は `tests/<名前>.test.mjs` です。実マイク、実電源断、長期効果の未確認を合成テストの成功で置き換えません。

## 実利用の比較記録

元設計に合わせ、A=今回の課題と明示条件だけ、B=旧版の全会話export JSONを共通の解答器へ添付、C=同じ元情報から作った確認済みpackをその解答器へ添付、で比較します。Bの解答器は旧版面談アプリの機能ではなく評価用の橋渡しです。同じ情報を揃える比較と、追加質問を含む製品全体の比較は分けます。失敗を含め、説明・修正・確認・待機時間を別々に記録します。個人の文章自体を集計ファイルに入れる必要はありません。

`node scripts/evaluate-context.mjs /path/to/trials.jsonl` で集計できます。一行は次の形式です。`cost:null`は不明でありゼロではありません。例は形式説明用の合成値です。

```json
{"condition":"C","success":true,"explanationSeconds":12,"editingSeconds":8,"confirmationSeconds":6,"waitingSeconds":15,"disclosureErrors":0,"correctionCount":1,"cost":null}
```

有料実測値を使う場合は`cost`とISO通貨コード`currency`を入れます。異なる通貨や未知費用を混ぜて合計しません。条件間の差は用途・難易度・順序効果を含むため、少数の差だけで全般的な効果を断定しません。

## 両立しないメモ

本人が編集画面で関連づけた`conflictsWith`を、ランキングで候補を減らす前に検査します。両方が同用途・場面・時期で利用候補になる間、出力と推論を止めます。一方の内容や範囲を直す・利用をやめる・関連づけを外すことで解決できます。自由文の意味的な矛盾の網羅的な自動検出は未実装です。
