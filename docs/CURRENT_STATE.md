# 実装の現在地

300問の設計を基に、暗号化保存、途中再開、本人による整理案の確認、訂正・削除、用途別の出力を実装しています。一問表示を中心に、管理操作はダイアログに置いています。主画面には質問・入力・次の操作・送信先を示し、保存の仕組みは設定で確認できます。操作できる要素には枠・背景とキーボードフォーカスを付けています。

| 入口 | 責務 |
| --- | --- |
| `src/core/vault.mjs` | 暗号化されたSQLite正本、トランザクション、版、依存失効、復元 |
| `src/core/crypto.mjs` | 標準暗号、鍵ラップ、暗号化バックアップ |
| `src/core/schema.mjs` / `proposals.mjs` | 用途・条件・期限・許可・根拠検査 |
| `src/interview/` | 300問、共通の質問目標、追質問予算、保留・拒否、根拠付き進捗 |
| `src/server/app.mjs` | ローカルHTTP、ブラウザーごとのロック、CSRF、資源制限 |
| `src/server/interview.mjs` | 保存後の任意推論、最小化した文脈、非同期結果の失効 |
| `src/server/legacy.mjs` | 明示的で非破壊の旧版取り込み |
| `src/server/provider.mjs` / `src/auth.mjs` | 任意のChatGPT接続 |
| `src/client.js` / `src/ui.html` | 一問表示、入力、途中再開、確認・編集・出力 |

入力をローカル保存してから、許可された場合だけ推論します。解釈は未確認候補で、原文・版・引用範囲を持ちます。画面に表示した版だけを採用できます。保留は未処理の義務ではありません。

新規保管庫と、まだ質問を始めていない旧データには、自由会話の入口から具体的な最初の質問を自動表示します。表示だけで外部送信はせず、再読込で質問位置も進めません。回答に合わせた次の質問にはChatGPT接続と送信の同意が必要で、画面上から設定できます。送信がオフの間は端末内に記録し、「別の問いへ」で進めます。

「今日はここまで」は質問位置と中断状態を保存します。再開操作は拒否した質問の解除と区別します。回答は毎回保存されるため、アプリの再起動にも残ります。書きかけは任意の24時間保存です。

300問を253個の共通目標へ対応付けました。類似質問のIDを変えても、拒否や追質問予算を回避しません。新規自由会話には18問の入口を使います。質問適用条件の全面的な自然言語推論や、全300問の利用者評価は未実施です。

## 現在の制約

- 保存期間の設定は、これから記録する発言に適用します。既存の発言をまとめて削除する設定ではありません。
- 単一端末・単一保管庫を対象にし、OS間同期、複数利用者、メール送信などの外部実行は対象外です。
- 検索は復号後の構造化フィルターと文字列一致です。ベクトルDBや全面的な意味検索は使いません。
- 時期は開始・終了、元の表記、日/月/季節/年などの精度で保存します。「去年の夏」などから日付範囲を自動で捏造しません。範囲未確定なら本人が用途に合う期間を指定してください。
- 自由文の例外があるメモは出力から除外します。条件を構造化するか、今回の判断に必要な情報を本人が調整します。
- 明示的に「両立を確認したい」と関連づけたメモは、同じ用途・条件・時期に当てはまる間、利用を止めます。無関係に登録された自由文同士の矛盾をすべて自動発見する機能ではありません。
- 本人の発言内に他人の引用が含まれる場合、話者判定の意味的な正しさまでは自動保証できません。
- 出力は手動コピー・ダウンロードです。ChatGPT内のメモリを読み書きしません。
- 実際の音声、長期的な説明・修正負担の削減は、自動テストと分けて検証します。

詳しい対応と未検証部分は [ACCEPTANCE.md](ACCEPTANCE.md) を参照してください。旧実装はGit履歴に残り、以前の保存ファイルはそのままです。

実サービス接続は合成の短文で、最初の質問の自動表示、回答保存、回答に応じた次の質問、中断・再読込・同じ質問からの再開まで確認しました。個人の記録や実音声はこの試験に使っていません。
