# 実装の現在地

この文書は設計レビューの入口です。実装済みの振る舞いと将来の製品構想を分けます。現行コードを最終設計として追認する必要はありません。

## コードの読み順

| ファイル | 現在の責務 |
| --- | --- |
| `src/questions.json` | 用途・暫定優先度付きの200問。個人に固有の過去記録を前提にしない公開用ベースライン |
| `src/interview-design.md` | 汎用の設計意図と200問の全文。呼び出しごとにモデルへ渡す |
| `src/interview-policy.md` | 一問ずつの会話、追質問、拒否・訂正・根拠付き整理の指示 |
| `src/conversation.mjs` | 原文保存、候補提示、プロンプト構築、出力検査、整理案と履歴の保存 |
| `server.mjs` | ローカルHTTP、認証・CSRF境界、モデル呼び出し、音声プロセスの管理 |
| `src/auth.mjs` | 任意の公式認証SDKを使う接続アダプター |
| `src/client.js` / `src/ui.html` | 一問表示、入力、停止、設定、原文一覧、JSON書き出し |
| `native/` | macOSの認証情報暗号化と音声認識 |
| `tests/` | 合成データによる保存・再試行・停止・認証・質問状態の検査 |

## 現在のデータの流れ

入力 → `raw_answer`を原文のまま保存 → 質問設計全文・整理状態・履歴をモデルへ送信 → JSONと原文引用を検査 → `ai_suggested`の状態更新を保存 → 次の一問を表示。

`question_states`は質問ごとに `partial / answered / unknown / on_hold / withheld` を保持します。`answered`はモデルが十分回答されたと判断した状態で、本人確認済みを意味しません。`source_message_id`と原文中の連続引用を保存します。訂正前の状態は`state_history`へ残します。既存の`coverage`は互換用の派生情報です。

保存はプロフィールごとのJSONです。ファイル権限は制限し、テンポラリファイルからrenameして置き換えます。重複要求IDを扱い、同一プロセス内の同時実行を抑制します。別プロセス同士の排他や、すべてのクラッシュ条件を保証する設計ではありません。

## まだできないこと

- 原文の文字起こしを本人が修正し、そこから派生した要約・検索結果・外部ファイルを一貫して更新すること
- 解釈・適用範囲・例外を本人が採用／保留／撤回する画面
- 確認済みの文脈をタスクごとに最小限抽出する検索・編集機構
- 他のAIへ用途別に渡すコンテキスト生成と、その更新・失効の管理
- 保持期限、削除、バックアップ復元、共有先ごとの権限管理
- 回答ファイルの暗号化、リモート複数利用者環境、Mac以外の音声・認証保護
- ChatGPTの既存の会話やメモリへのアクセス・書き戻し

記録全体のJSON書き出しはありますが、確認済み・用途別のコンテキスト出力とは異なります。

## レビュー時に注意する実装上の限界

原文の引用が一致していても、その要約が正しいとは限りません。現在は質問IDに状態を結びつけており、発言内の複数の意味や、質問をまたぐ訂正の扱いを再検討する必要があります。履歴を幅広く送信する方式は、長い会話での情報量・遅延・利用枠・プライバシーに影響します。

少数の合成会話と自動テストは、長期的な面談品質や説明し直しの削減を証明しません。実際の音声の往復も未検証です。公開版の200問は暫定資料であり、幅広い利用者に対する内容妥当性・優先度の評価は未実施です。

認証DevKitは非商用の別ライセンスで、Gitリポジトリには同梱していません。レビューにはコードだけでなく `LICENSES/README.md` も含めてください。
